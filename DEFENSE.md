# Защита MiniDB: сценарий на 5–7 минут

Перед защитой: `./minidb --reset --script seed.txt` (или использовать готовую папку `minidb_data/`).

## Ход показа

1. **Что это.** Файловая СУБД на C++17, всё написано вручную. Три таблицы: datasets, models, experiments, связи по внешним ключам.
2. **Открыть базу:** `./minidb`, затем `show tables` (5 / 5 / 20) и `describe experiments` (видны PK и FK).
3. **INSERT:** `insert into experiments values (21, 1, 1, 0.93, completed)`.
4. **SELECT:** `select * from datasets`; `select id, status, accuracy from experiments where accuracy > 0.9`; `select * from experiments where id = 21`.
5. **UPDATE / DELETE:** `update experiments set status = completed, accuracy = 0.8 where id = 3`; `delete from experiments where id = 21`.
6. **Ссылочная целостность:** `insert into experiments values (23, 99, 1, 0.5, failed)` и `delete from datasets where id = 1` дают ошибки.
7. **Перезапуск:** `exit`, снова `./minidb`, `select * from experiments where id = 3`. Изменения на месте.
8. Если время есть: JOIN, `backup minidb_backup`, `catalog.txt` и размер `.dat` (`ls -l minidb_data`).

Автоматический вариант шагов 2–6: `./minidb --script demo.txt`.

## Частые вопросы

**Как хранятся данные?** `catalog.txt` с метаданными и файл `<таблица>.dat` на каждую таблицу: записи фиксированной длины, первый байт флаг «жива / удалена».

**Как найти запись по номеру?** Смещение = номер × размер записи (97 байт для experiments).

**Что такое индекс и где он лежит?** Хеш-таблица `PK → смещение` в памяти. На диск не пишется, при открытии таблицы строится проходом по файлу. Работает для условия `id = число`; остальные условия идут полным проходом.

**Как работает DELETE?** Флаг записи = 0, ключ убирается из индекса. Физически место освобождает `compact`.

**Как работает UPDATE?** Находятся подходящие записи вместе с их смещениями, затем каждая перезаписывается на своём месте. PK менять нельзя.

**Как проверяется внешний ключ?** При INSERT и UPDATE ищется значение среди PK родительской таблицы (через индекс); при DELETE родителя проверяется, что в дочерней таблице нет ссылок.

**Как запрещаются дубликаты PK?** Перед записью смотрим в индекс; если ключ есть, ошибка `duplicate primary key`.

**Почему не реализованы AND / OR?** Они нужны только для высшей оценки; в условии поддерживается одно сравнение.

**Что будет при отключении питания?** Гарантий нет: нет журнала и fsync. Данные сбрасываются в файл после каждой операции. Каталог пишется через временный файл и `rename`.

**Зачем compact?** Удалённые записи остаются в файле как «могилы»; compact переписывает файл без них.

**Что в бенчмарке?** Поиск по id через индекс против полного прохода на 1 000 / 10 000 / 50 000 строк: ускорение от ×20 до ×900 (зависит от машины).
