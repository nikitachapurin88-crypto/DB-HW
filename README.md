# MiniDB

Файловая мини-СУБД на C++17 (лабораторная работа №1). Без SQLite/PostgreSQL/MySQL, ORM и pandas:
всё хранение, индекс, проверка ключей и разбор команд написаны вручную.

## Что умеет

- таблицы с типами `INT`, `FLOAT`, `STRING` (до 64 байт) и первичным ключом (INT);
- `INSERT`, `SELECT` (все столбцы или выбранные, одно условие `= != > < >= <=`), `UPDATE`, `DELETE`;
- запрет дубликатов PK;
- внешние ключи с проверкой ссылочной целостности: нельзя добавить/изменить эксперимент с несуществующим
  `dataset_id` / `model_id`, нельзя удалить датасет или модель, на которые есть ссылки, нельзя удалить таблицу, на которую ссылаются;
- `JOIN` по равенству столбцов, `backup`, `compact`, индекс по PK;
- данные сохраняются между запусками (папка `minidb_data/`).

Не реализовано: `AND` / `OR` в условиях, транзакции, журнал, fsync.

## Схема

| Таблица | Столбцы |
|---|---|
| `datasets` | `id` PK, `name`, `task`, `size` |
| `models` | `id` PK, `name`, `version` |
| `experiments` | `id` PK, `dataset_id` FK → `datasets.id`, `model_id` FK → `models.id`, `accuracy` FLOAT, `status` |

DBML для dbdiagram.io: `schema.dbml`.

## Сборка и запуск

Нужны g++ с поддержкой C++17 (или CMake).

```bash
g++ -std=c++17 -O2 table.cpp database.cpp cli.cpp main.cpp -o minidb
./minidb                      # интерактивный режим, база в ./minidb_data
./minidb --script demo.txt    # прогнать сценарий защиты
./minidb --reset --script seed.txt   # пересоздать базу с тестовыми данными
./minidb --db другая_папка    # другая папка базы
```

Через CMake: `cmake -S . -B build && cmake --build build` (цели `minidb`, `minidb_tests`, `minidb_bench`).

Папка `minidb_data/` в репозитории уже содержит готовую базу: 5 datasets, 5 models, 20 experiments.

## Команды

```
create table <имя> (<столбец> <тип>, ...) primary key <столбец> [foreign key <столбец> references <таблица>.<столбец>] ...
insert into <таблица> values (v1, v2, ...)
select * | col1, col2 from <таблица> [where <столбец> <оператор> <значение>]
select * from A join B on A.col = B.col
update <таблица> set col = v [, col = v] [where ...]
delete from <таблица> [where ...]
show tables | describe <таблица> | drop table <таблица> | compact <таблица> | backup <папка> | help | exit
```

Строки с пробелами пишутся в кавычках: `'two words'`. Команды нечувствительны к регистру. Условие без `where` затрагивает все строки.

Примеры:

```
select id, status from experiments where accuracy > 0.9
update experiments set status = completed where id = 3
insert into experiments values (23, 99, 1, 0.5, failed)    -- error: foreign key violation
```

## Архитектура

| Файл | Роль |
|---|---|
| `exceptions.h` | типы ошибок (дубликат PK, несовпадение типа, нарушение внешнего ключа, ...) |
| `table.h/.cpp` | одна таблица: файл `<имя>.dat`, записи фиксированной длины, индекс PK → смещение, поиск, вставка, изменение, удаление |
| `database.h/.cpp` | набор таблиц, каталог `catalog.txt`, внешние ключи, JOIN, backup, compact |
| `cli.h/.cpp` | разбор текстовых команд и вывод таблиц |
| `main.cpp` | запуск: интерактивный режим, `--script`, `--reset` |
| `tests.cpp` | автотесты движка |
| `bench.cpp` | замер скорости поиска с индексом и без |
| `seed.txt`, `demo.txt` | тестовые данные и сценарий защиты |

### Формат хранения

- `catalog.txt`: строка на таблицу, `имя;столбец:тип;...;fk=столбец>таблица.столбец;...;pk=столбец`. Записывается через временный файл и `rename`.
- `<таблица>.dat`: записи подряд. Запись = 1 байт флага (1 жива, 0 удалена) + столбцы: INT и FLOAT по 8 байт, STRING 64 байта с добивкой нулями. Размеры: datasets 145, models 137, experiments 97 байт.
- Смещение записи с номером k = `k * размер записи`.

### Как работают операции

- **INSERT**: проверка типов и длины строки, проверка внешних ключей (поиск по PK родителя), проверка дубликата PK через индекс, запись в конец файла.
- **SELECT**: при условии `pk = число` берётся смещение из индекса и читается одна запись, иначе проход по файлу с пропуском удалённых; затем оставляются нужные столбцы.
- **UPDATE**: сначала проверяются все изменения (типы, PK менять нельзя, новые внешние ключи должны существовать), затем найденные записи перезаписываются на тех же смещениях.
- **DELETE**: проверяется, что на удаляемые строки никто не ссылается; затем флаг записи = 0 и ключ убирается из индекса. Место освобождает `compact`.
- **Индекс**: хеш-таблица `PK → смещение` в памяти. На диск не пишется, при открытии таблицы строится проходом по файлу.

## Тесты и бенчмарк

```bash
g++ -std=c++17 -Wall -Wextra -fsanitize=address,undefined table.cpp database.cpp cli.cpp tests.cpp -o tests && ./tests
g++ -std=c++17 -O2 table.cpp database.cpp bench.cpp -o bench && ./bench
```

Результаты бенчмарка (Linux, g++ 13.3, -O2; поиск по `id` через индекс против полного прохода):

| Строк | Без индекса, мкс | С индексом, мкс | Ускорение |
|---|---|---|---|
| 1 000 | 38 | 1,7 | ×23 |
| 10 000 | 400 | 1,8 | ×226 |
| 50 000 | 2185 | 2,5 | ×870 |

Значения зависят от машины и меняются между запусками; запустите `./bench` у себя.
