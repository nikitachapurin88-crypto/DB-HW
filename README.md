# MiniDB

Файловая мини-СУБД на C++17 для лабораторной №1. Собственный формат хранения, метаданные таблиц, CRUD, первичный ключ и типы, три связанные таблицы, JOIN, backup и индекс `id → offset`. Без SQLite, PostgreSQL, pandas и ORM: всё, что связано с хранением, написано вручную.

## Запуск

Нужен компилятор с поддержкой C++17 (g++ 9+, clang++ 9+, MSVC 2019+).

```bash
# без CMake
g++ -std=c++17 -O2 -o minidb       main.cpp  table.cpp database.cpp
g++ -std=c++17 -O2 -o minidb_tests tests.cpp table.cpp database.cpp
g++ -std=c++17 -O2 -o minidb_bench bench.cpp table.cpp database.cpp

# или через CMake
cmake -S . -B build && cmake --build build
```

| Команда | Что делает |
|---|---|
| `./minidb` | демо: при первом запуске создаёт три таблицы и выполняет CRUD, JOIN и backup; при повторном показывает, что данные сохранились |
| `./minidb --reset` | удаляет базу (`minidb_data/`) и копию (`minidb_backup/`) |
| `./minidb_tests` | автоматические тесты; при успехе печатает `All tests passed.` |
| `./minidb_bench` | benchmark индекса: полный проход против поиска по индексу |

База создаётся в текущей папке, откуда запущена программа.

## Структура проекта

| Файл | Назначение |
|---|---|
| `exceptions.h` | классы ошибок (`DuplicateKey`, `TableNotFound`, `TypeMismatch` и др.) |
| `table.h`, `table.cpp` | одна таблица: формат записи, индекс, INSERT / SELECT / UPDATE / DELETE, `compact` |
| `database.h`, `database.cpp` | набор таблиц и каталог `catalog.txt`: создание и удаление таблиц, JOIN, backup |
| `main.cpp` | демонстрационный сценарий |
| `tests.cpp` | тесты |
| `bench.cpp` | benchmark индекса |
| `CMakeLists.txt` | сборка |

## Архитектура

```
main.cpp / tests.cpp / bench.cpp      пользователь базы
              │
          Database                    таблицы по имени, каталог, JOIN, backup
              │
            Table                     один файл: формат записи, индекс, CRUD
              │
        файлы на диске                catalog.txt + <таблица>.dat
```

`Database` хранит словарь `имя → Table` и файл метаданных `catalog.txt` со схемами. Операции CRUD она только передаёт нужной таблице. `Table` владеет файлом данных и индексом, проверяет типы и уникальность ключа. Каждый слой знает только о нижнем.

## Формат хранения

Директория базы (`minidb_data/`):

```
minidb_data/
├── catalog.txt        метаданные: по строке на таблицу
├── students.dat       данные таблицы students
├── courses.dat
└── enrollments.dat
```

**`catalog.txt`.** Одна строка на таблицу: имя, столбцы `имя:тип`, первичный ключ.

```
students;id:int;name:text;age:int;pk=id
```

Каталог записывается во временный файл и переименовывается поверх старого, поэтому сбой посреди записи не оставляет повреждённый файл.

**`<таблица>.dat`.** Записи фиксированной длины подряд, без заголовка:

```
[флаг: 1 байт][столбец 1][столбец 2]...
флаг: 1 = запись жива, 0 = удалена (tombstone)
int, float -> 8 байт;   text -> 64 байта, добивается нулями
```

Для `students (id int, name text, age int)` запись занимает 1 + 8 + 64 + 8 = 81 байт, смещение записи с номером `k` равно `k * 81`.

**Индекс `id → offset`.** Хеш-таблица в памяти: значение первичного ключа → смещение записи в файле. Файла индекса нет: при открытии таблицы он строится заново одним проходом по `.dat`, поэтому не может разойтись с данными. Условие вида `id = число` читает запись одним `seek`, остальные условия просматривают файл целиком.

**Удаление.** DELETE ставит записи флаг 0 и убирает ключ из индекса. Физически строки убирает `compact`: он переписывает файл без удалённых записей и перестраивает индекс.

## Реализованные функции

**Database**

| Метод | Что делает |
|---|---|
| `Database(dir)` | открывает базу в папке `dir`, создаёт её при отсутствии, загружает каталог |
| `create_table(name, schema)` | создаёт таблицу; проверяет имя и схему; при сбое откатывает изменения |
| `drop_table(name)` | удаляет таблицу и её файл |
| `has_table`, `list_tables`, `schema` | сведения о таблицах |
| `insert(table, row)` | добавляет строку |
| `select(table, cond)` | выборка; без условия возвращает все строки |
| `update(table, cond, changes)` | изменяет найденные строки, возвращает их число |
| `remove(table, cond)` | удаляет найденные строки, возвращает их число (`delete` в C++ ключевое слово) |
| `join(left, right, left_col, right_col)` | соединение двух таблиц по равенству значений столбцов |
| `backup(dest)` | копия всей базы в папку `dest`; восстановление: `Database(dest)` |
| `compact(table)` | физически убирает удалённые записи |

**Типы и условия.** Типы столбцов: `Int` (64 бита), `Float` (double), `Text` (до 64 байт). Первичный ключ только `Int`, менять его через UPDATE нельзя. Условие: `столбец <операция> значение`, операции `=`, `!=`, `<`, `<=`, `>`, `>=`. Составные условия (AND, OR) не поддерживаются.

**Пример.**

```cpp
Database db("minidb_data");
db.create_table("students", Schema{{{"id", ColumnType::Int},
                                    {"name", ColumnType::Text},
                                    {"age", ColumnType::Int}}, 0});

db.insert("students", Row{std::int64_t(1), std::string("Alice"), std::int64_t(19)});
auto rs = db.select("students", Condition{"age", Op::Gt, std::int64_t(20)});
db.update("students", Condition{"id", Op::Eq, std::int64_t(2)},
          Changes{{"age", std::int64_t(25)}});
db.remove("students", Condition{"id", Op::Eq, std::int64_t(3)});
auto joined = db.join("enrollments", "students", "student_id", "id");
```

Ошибки сообщаются исключениями (`DuplicateKey`, `TableNotFound`, `TypeMismatch`, `InvalidName` и др.), все они наследуются от `DatabaseError`.

## Схема данных

Демо создаёт три таблицы. Схема в формате [dbdiagram.io](https://dbdiagram.io) (DBML):

```
Table students {
  id int [pk]
  name text
  age int
}

Table courses {
  id int [pk]
  title text
  credits int
}

Table enrollments {
  id int [pk]
  student_id int
  course_id int
  grade float
}

Ref: enrollments.student_id > students.id
Ref: enrollments.course_id > courses.id
```

Связи логические: движок не проверяет внешние ключи, они используются только в `join`.

## Benchmark индекса

`./minidb_bench` сравнивает два запроса, возвращающие одну и ту же строку: `WHERE id = k` (через индекс) и `WHERE code = k` (столбец `code` не проиндексирован, полный проход).

| Строк | Размер файла | INSERT, мс (всего) | Открытие + индекс, мс | Без индекса, мкс/запрос | С индексом, мкс/запрос | Ускорение |
|---|---|---|---|---|---|---|
| 1000 | 79 КБ | 0.9 | 0.1 | 35.5 | 1.3 | ×27 |
| 10000 | 791 КБ | 9.6 | 0.9 | 283.2 | 1.3 | ×224 |
| 50000 | 3955 КБ | 48.4 | 3.6 | 1701.4 | 1.5 | ×1109 |

Измерено на Linux x86_64, 2 ядра, g++ 13.3 с `-O2`; 10000 запросов по индексу и 100 по полному проходу на каждый размер. Время без индекса растёт линейно с числом строк, время с индексом остаётся постоянным. Между двумя запусками значения менялись на 10–15 %, порядок величин сохранялся (на 50000 строк ускорение составило ×956 и ×1109). Абсолютные числа зависят от машины, поэтому для отчёта лучше запустить `./minidb_bench` у себя.

## Тесты

`./minidb_tests` проверяет: создание таблиц и ошибки схемы, INSERT и SELECT с разными условиями, ошибки ввода (дубликат ключа, неверный тип, слишком длинный текст), UPDATE и DELETE, повторное использование освободившегося ключа, перезапуск базы, JOIN, backup, `compact` и `drop_table`. Тесты также проходят под AddressSanitizer и UBSan (`g++ -fsanitize=address,undefined`).

## Ограничения

- Журналирования нет: аварийное завершение посреди записи может оставить запись в промежуточном состоянии. Данные записываются в файл после каждой операции (`flush`), но на диск принудительно (`fsync`) не сбрасываются.
- Один процесс: защиты от одновременной работы нескольких процессов с одной базой нет.
- Индекс только по первичному ключу, остальные условия просматривают файл целиком.
- Внешние ключи не проверяются.
- JOIN вложенными циклами, O(n·m), обе таблицы читаются в память.
- Текст ограничен 64 байтами (кириллица в UTF-8 занимает 2 байта на символ), файл `.dat` зависит от архитектуры (порядок байт).
